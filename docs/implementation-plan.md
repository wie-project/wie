# WIE implementation plan — waves toward high-FPS emulation of any app

Source analysis: `docs/architecture-review-games-and-apps.md` (painpoint
catalog A–E and decision options). This file is the sequenced, executable
version of that review's roadmap, with live status. Update the status column
as waves land; do not restate rationale here.

Conventions that apply to every wave: workspace lints deny
`unwrap_used`/`expect_used`/`panic`/`indexing_slicing`/`as_conversions`
(use `?`, `.get()`, `try_from`); `unsafe` only in `wie-cpu`; pre-PR gate
`./scripts/check.sh`; micro-suite `make -C micro-exes &&
./scripts/run-micro-suite.sh`; all timing on release builds only.

| Integer SSE via existing scalar helpers widened to packed forms | ✅ **broad packed SSE work landed 2026-09-05–07** — commits including `e537652`, `fb7d22c`, `895fff8`, and `fd12b41` add packed integer/SSE lowering and interpreter coverage. The next ISA family must be selected from an opcode/stop histogram rather than assumed speculatively. |
| Coverage metric: % of micro-suite instructions executed without stop | 🟡 **metric shipped 2026-09-26, denominator defective** — `WIE_RUNTIME_PROFILE` now prints `insn_coverage:` (total/jit/iced/`jit_share_pct`/degraded/`degraded_pct`/`stops_per_1k`/`block_entries`/`insn_per_entry`, `basis=block_entry_static`) plus an `insn_coverage_caveat:` line on every profiled run including headless; `./scripts/coverage-report.sh` aggregates 62 micro exes into `docs/baselines/insn-coverage.txt`. **Two known denominator defects, deliberately labelled rather than papered over:** (a) `jit_insns` charges a block's STATIC length per entry (`jit/pipeline.rs:1100`, `jit/lower/mod.rs:1237`), so a self-looping block undercounts by its trip count — `long_loop` reports 25 for ~3×10⁸ retired; (b) `cpu_stats()` does not merge worker engines (`mt_runtime.rs:371-378`), so `cpp_threads` interprets 26407 instructions and reports `iced=45`. Only `degraded`, and `iced_insns` on a single-thread guest, are exact. **Consequence:** the `iced_ratio` values in `docs/baselines/wave2-acceptance.txt` are block-entry ratios, not instruction ratios, and are affected by (a). Use the metric to RANK ISA families, never as a throughput figure. A real denominator needs a per-block trip counter in the lowering step plus a cross-thread stats merge. |
| Next ISA family, chosen from the histogram | ✅ **selected 2026-09-26: `Pause` (F3 90)** — exact interpreted mix over the micro-suite (54858 instructions): `Pause` 32683 (**59.5%**, 100% of it the `cpp_threads` worker spin loop), `Call` 12593 (22.9%), `Jmp` 4940 (9.0%), `Lea` 4222 (7.6%), `Mov` 334 (0.6%). `Mnemonic::Pause` is missing from the lowerer's no-op arm (`jit/lower/insn.rs:291-299`), so any block containing it fails to lower whole. Runner-up is **not an ISA family**: `Call`+`Jmp` = 39% is block-edge formation (call/ret/direct-branch chaining). **No SSE/x87/mm family appears in the residue at all**, so micro-suite data gives no support for a vector-ISA target — that needs a real-app profile (7za). |

| DirectInput/RawInput pass-through; winit event → guest queue without big lock | ✅ **RawInput landed 2026-09-26 (synthesized)** — `crates/wie-winapi/src/user32/raw_input.rs` implements the API surface for real (`RegisterRawInputDevices`, `GetRegisteredRawInputDevices`, `GetRawInputDeviceList`, `GetRawInputDeviceInfoA/W`, `GetRawInputBuffer`, `GetRawInputData`, `DefRawInputProc`) plus `WM_INPUT` delivery, replacing four fake stubs that returned failure/zero-devices. Guest struct layouts are read from the local mingw-w64 headers, not guessed, with a guest-layout regression test as the guard. **Two views of one buffered input**, fed from `RawInputState::publish`: `delivered` is keyed by a fake `HRAWINPUT`, capped, and **never consumed** (so `GetRawInputData(lParam)` stays valid); `buffered` is the FIFO `GetRawInputBuffer` serialises from and **drains** (capped). A drain therefore cannot invalidate an `lParam` the guest still holds, and the return value counts only the buffer view, so nothing is double-counted. Size queries and under-sized buffers stay non-consuming. **Documented deviations:** (a) macOS exposes no raw HID stream and winit has no portable raw-input event, so `RAWINPUT` payloads are **synthesized** from the keyboard/mouse state WIE already tracks — the same compromise Wine makes off-Windows, not true hardware raw input; (b) `GetRawInputBuffer` is **not per-thread** — WIE has one process-wide raw-input queue fed by the single winit event thread, so it serves the whole queue rather than inventing a threading model for one function. The host path keeps the no-big-lock discipline. |
| Multi-queue message pump per thread (`user32/message` was single-queue until this row) | ✅ **landed 2026-09-26** — `present/queue.rs` holds one `MessageQueues` of per-TID FIFO sub-queues behind the single queue mutex; `WindowRecord.owner_tid` (set in `create_window_record`) routes `PostMessage` to the window's thread, `PostThreadMessageW` became a real push into the named TID's queue (it used to be a fake success that dropped the message), and `GetMessage`/`PeekMessage`/`WM_TIMER`/`WM_PAINT` synthesis scan only `current_tid()`'s sub-queue. `WM_QUIT` still bypasses both filters. Host posts keep the "locks only the queue mutex" discipline via a mirrored `hwnd → owner_tid` index and fall back to the primary tid. Still open: inter-thread `SendMessage` marshaling, `HWND_BROADCAST`, and per-thread (not broadcast) wake targeting. |
| DirectInput8 (`dinput8.dll`) | ✅ **keyboard + mouse shim** — `DirectInput8Create` → real `IDirectInput8` (11-slot) + `IDirectInputDevice8` (32-slot) guest vtables, dispatched over WIE's existing keyboard/mouse state; `EnumDevices` walks both devices through the full-iteration callback bridge (a 3-line router in `gdi32/enumerate.rs`, kept off `pump.rs` deliberately); `GetDeviceState` synthesizes `DIDEVICEOBJECTDATA` by reading the guest's own `DIDATAFORMAT`/`DIOBJECTDATAFORMAT` array and honouring the offsets the guest declared, rather than hardcoding a report layout. `CreateDevice` for any other class, all force feedback, all action maps, and all buffered event calls fail with a specific `HRESULT`. **No joysticks, gamepads, flight controls, HID, or FF.
