# Lane S1 — ROOT CAUSE FOUND

## The bug (byte-level verified, v16 trace event ~10885555)

Doom Retro parses its resource wad's DEHACKED lump through `mem_fgets` (lump path,
NO text-mode CRLF translation — unlike `fopen(...,"rt")`). Each line lands in
`inbuffer` as `"[STRINGS]\r\n\0"`.

`lfstrip()` should strip the trailing `\r\n`:
```c
char *p = s + strlen(s);
while (p > s && (*(--p) == '\r' || *p == '\n')) *p = 0;
```

Under WIE, the section-dispatch compare observes `inbuffer = "[STRINGS]\r"` with
`'\r'` STILL PRESENT at offset 9 (and presumably NUL at 10):
- `strncasecmp("[STRINGS]\r", "[STRINGS]", 9)` matches all 9 chars…
- …but the caller's count came out ≥10 (the walk continued into `entry[9]=0x00`
  vs `line[9]='\r'`) → mismatch → `[STRINGS]` section NEVER entered →
  `deh_procStrings` processes nothing → `s_VERSION` stays `""` → version `I_Error`.

## Why `\r` survival matters

With `\r` appended, EVERY section/key compare in the DEHACKED walk mismatches at
the terminator byte. Zero `deh_strlookup` assignments occur (verified: widened
store-watch across the whole lookup array → 0 heap reassignments; MODE global = 0,
so the case-folding compare path was active and correct).

## Remaining unknown (one probe away)

WHY the `\r` survives lfstrip:
- H1: `lfstrip`'s `strlen(s)` mis-executes under WIE for THIS buffer state
  (`"[STRINGS]\r\n"` — first qword has no NUL; second qword begins `\r\nVe…`),
  returning ≤9 so `p` never reaches the `\r`.
  NOTE: an isolated unit test of the haszero ALU chain (both engines) PASSES —
  so if H1 holds, the divergence needs surrounding context (e.g., the load
  feeding `%rdx`, flags, or the specific buffer address/alignment).
- H2: `mem_fgets` in the shipped binary stops at `\r` (treats it as terminator)
  AND lfstrip's strlen sees `"[STRINGS]\r"` len=9, strips `[8]='\r'` → leaves
  `"[STRINGS]\n"` — which contradicts the observed `[9]='\r'`… unless the
  observed compare used a DIFFERENT buffer than the stripped one (two inbuffers:
  D_ProcessDehFile's vs deh_procStrings' local copy made via
  `strncpy(inbuffer, line, …)`).
