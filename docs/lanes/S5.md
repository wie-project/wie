# Lane S5 — kernel32/file_io hot path (ReadFile / SetFilePointerEx)

Scope: ONLY `crates/wie-winapi/src/kernel32/file_io/{open.rs,rw.rs,mod.rs}`.

Baseline (debug, WIE_RUNTIME_PROFILE, Doom Retro):
- readfile 3174 calls / 151.83 ms (~47.8 µs/call)
- setfilepointerex 2898 calls / 59.59 ms (~20.6 µs/call)
Target: combined ≤50 ms (debug).

Facts gathered before touching code:
- Whole guest files are staged fully in memory at open (`resolve_guest_file_bytes`
  log line "resolved guest file bytes ... bytes=8075616" = freedoom2.wad);
  non-streaming `OpenGuestFile.bytes` is the resident mirror.
- ReadFile (buffered path) currently performs ~5 separate `open_files` hash
  lookups per call:
  1. `is_open_file_handle` (validity)
  2. `sync_host_cursor_from_guest` → `open_files.get_mut` (guest-table cursor pull)
  3. `find_open_file` (streaming probe)
  4. Phase 1 `find_open_file_mut` (bounds + cursor advance) + `path.clone()` + `is_main_module_path`
  5. Phase 2 `find_open_file` (slice + mem_write)
  6. tail `find_open_file` for the tracing::info line
  plus `sync_slot_from_host` (7th lookup) writing size+cursor u64s to the
  guest table every read.
- SetFilePointerEx currently: `is_open_file_handle` → `find_open_file_mut`
  → `size()` → write_guest_u64 → `sync_cursor_to_guest_table` (re-lookup +
  slot math + write_guest_u64).
- Dirty-flag contract (`state/tests/guest_io_dirty.rs`): `sync_slot_from_host`
  writes cursor/size u64s EVERY call, but re-mirrors O(filesize) arena bytes
  ONLY when `guest_dirty`. Reads must NEVER set dirty; writes must set it and
  flush the flag after mirror.
